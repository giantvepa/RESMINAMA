# RESMINAMA СЭД — версия 0.3.0, сборка 3

Локальная система электронного документооборота для Windows, 26 сентября 2026 года.
Версия 0.2.0 сохраняется как стабильная контрольная поставка. Версию 0.3.0 устанавливайте в отдельную папку.

## Обновление с v0.2.0 или предыдущей сборки v0.3.0

1. Остановите старый сервер: Ctrl+C в его окне.
2. Выполните **BACKUP.bat** из старой версии. Сохраните старую папку целиком.
3. Распакуйте новый архив в отдельную папку, например `C:\RESMINAMA_SED_v0.3.0`.
4. **До первого START.bat** запустите в новой папке **IMPORT_DATA.bat**.
5. Укажите путь к старой папке, например `C:\RESMINAMA_SED_v0.2.0`.
6. После успешного переноса запустите новый **START.bat** и войдите с прежними логином и паролем.
7. Сравните документы, вложения и права на нескольких своих карточках.

Старая папка не изменяется. Перенос сохраняет документы, пароли, права, шаблоны маршрутов, историю и вложения. Существующая база в новой папке не перезаписывается. Если вы уже запустили новую версию, распакуйте архив в ещё одну пустую папку и повторите перенос.

При первом запуске база автоматически обновляется. До обновления сохраняется копия SQLite в `data/migration_backups`. Поддерживается также перенос из v0.1 и восстановление данных v0.3. База более новой версии отклоняется.

Поручения, перенесённые из v0.2, сохраняют прежний способ завершения. Новые поручения v0.3 требуют отчёта и приёмки. Видимость существующих документов остаётся прежней. Для ранее архивированных документов срок хранения отмечается как **не установлен при переносе**: приложение не назначает его задним числом.

**Откат:** остановите v0.3 и запустите сохранённую папку v0.2. Изменения, сделанные после перехода, в ней отсутствуют. Не подключайте обновлённую базу v0.3 к серверу v0.2. Пока проверяете новую версию, вводите рабочие данные только в одной выбранной системе.

## Первый запуск без старых данных

Нужен установленный **Python 3.10+**, рекомендуемый для вашей среды — имеющийся Python 3.12. Python не включён в архив.

1. Распакуйте архив полностью. Не запускайте BAT прямо из ZIP.
2. Откройте **START.bat**. Оставьте окно сервера открытым.
3. Браузер откроет `http://127.0.0.1:8000`.
4. Случайные первоначальные пароли находятся в **data/ACCOUNTS.txt**. Для управления войдите как `admin`.
5. Смените пароли в меню профиля. После передачи паролей сотрудникам удалите ACCOUNTS.txt.

Интернет, Docker, Node.js, Microsoft Office и установка библиотек через pip для запуска СЭД не требуются. Для редактирования скачанного DOCX используйте установленный Word или ONLYOFFICE Desktop Editors.

Первоначальные пользователи: admin, secretary, legal, finance, it, director. Администратор может переключать действующего участника в меню профиля для демонстрации. Журнал сохраняет и участника, и реальный логин администратора.

Для новой базы без примерных документов **до первого обычного запуска** выполните:

```bat
py -3 server.py --empty
```

Этот ключ не удаляет существующую базу. Если `py` отсутствует, используйте `python`. Если порт занят: `py -3 server.py --port 8001`.

## Согласование по frame-007

Вкладка **Согласование** показывает графическую схему с дорожкой каждого сотрудника: начало, параллельные ветки или последовательная очередь, объединение решений, возврат на доработку и следующий этап (обычно утверждение). Цвет и текст блока показывают фактическое решение. Нажатие на блок открывает комментарий и дату решения, если они сохранены в истории.

Карточки со статусом «На согласовании» или «На утверждении» сразу открываются на этой вкладке. Справа доступны действия текущего сотрудника: согласовать/утвердить, отклонить с причиной; автору доступны изменение участников и отмена процесса. В универсальном маршруте администратор также может отменить процесс. Изменения сохраняются сразу; отдельные «Сохранить» и «Сохранить и закрыть» не требуются.

Схема работает и для перенесённых документов с прежним согласованием, и для новых шаблонов. Для универсальных процессов можно выбрать предыдущую итерацию (только просмотр), а при нескольких согласованиях — нужный этап. В архиве доступен только просмотр. Если выбранный маршрут не содержит согласования, вкладка объясняет это и предлагает открыть **Маршрут**. На узком экране схема прокручивается по горизонтали.

Проверка с конкретными ролями: **FRAME007_RU.md**. Исправление не меняет структуру базы и настройки маршрутов.

## Типы документов и шаблоны процессов

В этой сборке реализован первый приоритет v0.3: универсальные типы и маршруты. В меню **Типы документов** администратор задаёт название, уникальный префикс номера, базовую группу, дополнительные поля и маршрут по умолчанию. Поля поддерживают текст, многострочный текст, дату, число, список, да/нет и сотрудника; можно сделать поле обязательным. Код поля — уникальная латиница, цифры и подчёркивания, начиная с буквы.

В поставке восемь типов: **Входящее письмо, Исходящее письмо, Служебная записка, Договор, Приказ, Заявка, Протокол, Внутренний документ**. Префиксы соответственно ВХ, ИСХ, СЗ, ДГ, ПР, ЗАЯВ, ПРОТ, ВН. Нумерация ведётся отдельно по префиксу и году. Отключение типа запрещает его использование в новых карточках, сохраняя старые документы.

В разделе **Процессы** администратор собирает маршрут из этапов: согласование, утверждение, резолюция, исполнение, регистрация подписанного файла, ознакомление, регистрация ответа/отправки, архив. Этапы можно переставлять стрелками. Внутри согласования доступны параллельный и последовательный порядок; очередь сотрудников также задаётся стрелками. «Автор документа» подставляется при запуске. После резолюции обязательно идёт исполнение; архив — последний этап.

Начальные маршруты включают входящее письмо через руководителя и ответ; договор через Юриста, Финансы и IT; приказ через согласование, подпись и ознакомление; служебную записку с исполнением получателем. У всех восьми типов есть начальный шаблон.

При создании карточки пользователь выбирает маршрут. Карточка сохраняет копию настроек типа и маршрута: последующее редактирование справочников не переписывает уже созданные документы. Автор либо редактор запускает процесс. Автор или администратор может изменить участников текущего и будущих этапов с причиной. На текущем этапе исполнения переназначайте поручения через их карточки.

Резолюция сохраняет текст руководителя, исполнителей, контролёра и срок. Каждый исполнитель получает обязательное поручение. Следующий этап открывается после приёмки всех результатов. Возврат согласования на доработку и новый запуск создают следующую итерацию; отмена процесса сохраняет историю и отменяет его открытые поручения.

На этапе подписи ответственный загружает уже подписанный PDF/DOCX. Это регистрация предоставленного файла, без создания и проверки ЭЦП. На этапе ответа укажите содержание, получателя, дату, способ отправки и приложите отправленный PDF/DOCX. Для входящего документа создаётся связанное исходящее письмо с отдельным номером и файлом; его дополнительные обязательные реквизиты заполняются в форме ответа. Почту приложение не отправляет.

Старые документы продолжают прежний маршрут. Раздел **Согласование v0.2** и вариант ручного согласования оставлены для совместимости. Перед проверкой новой схемы создайте новую карточку. Подробный сценарий: **SCENARIO_CENTRAL_BANK_RU.md**.

## Карточка документа

Все типы документов получают автоматический регистрационный номер. Карточка содержит дату документа и регистрации, внешний номер и дату, корреспондента, подразделение, содержание, срок, приоритет, категорию, метки, дело и связи с другими документами. Общие дополнительные поля — организация, куратор и основание. У договора дополнительно есть сумма, валюта, условия оплаты, начало и окончание обязательств, контактное лицо и НДС.

Карточка объединяет реквизиты, поручения, вложения, согласование, ознакомление, доступ, журнал и обсуждение. Связанные документы показываются только тем сотрудникам, у которых есть доступ. Скрытая от редактора связь сохраняется при изменении карточки.

Реквизиты и файлы изменяются в черновике и на доработке. После утверждения или завершения автор либо администратор может нажать **Открыть доработку**, указав причину. Активные поручения и ознакомления сначала нужно завершить. Решения согласующих сбрасываются, история сохраняется, новый вариант проходит согласование заново. Для архивного документа сначала нужен возврат из архива.

Меню **⋯ → Карточка в DOCX** выгружает текущие реквизиты, участников и решения, перечень последних версий вложений, поручения и архивную запись. Сами вложения в эту выгрузку не встраиваются. Есть также печать карточки и копирование ссылки.

В реестре работают поиск по названию, номеру, корреспонденту, содержанию, внешнему номеру, категории и меткам, фильтры типа и статуса, сортировка и CSV. Архив имеет отдельный поиск. Кнопка **Обновить данные** в верхней панели загружает изменения коллег. При одновременном изменении система отклоняет сохранение устаревшей ревизии и обновляет данные: повторите своё действие после проверки карточки.

## Права доступа

| Участник | Возможности |
|---|---|
| Автор | Подготовка карточки, права, маршрут, поручения, ознакомление и архивирование своих готовых документов |
| Дополнительный читатель | Просмотр, скачивание вложений, комментарии до архивирования |
| Редактор документа | Реквизиты и файлы в черновике/на доработке, запуск согласования, поручения и ознакомление |
| Согласующий | Решение в назначенном этапе; при последовательном маршруте — после предыдущего |
| Утверждающий | Утверждение после согласующих, поручения, ознакомление и архивирование доступного готового документа |
| Исполнитель | Взять своё поручение, заполнить отчёт и передать результат на приёмку |
| Инициатор/контролёр поручения | Принять или вернуть результат, изменить исполнителя/контролёра/срок, отменить с причиной |
| Архивариус | Все архивные документы, ведение дел и сроков хранения, возврат из архива; обычные правила доступа к неархивным документам |
| Администратор | Все документы, пользователи, права, дела, блокировки файлов и демонстрация от имени сотрудников |

Вкладка **Доступ** позволяет открыть документ всей организации, назначить читателей и редакторов. Права меняют автор и администратор. Назначенные участники получают просмотр автоматически; простое удаление из списка читателей не отменяет участие в маршруте или поручении. Инициаторы поручений сохраняют доступ к связанному документу. В архиве заблокированы все изменения карточки, включая доступ, новые поручения, процессы и ознакомление. Сначала требуется возврат из архива архивариусом или администратором.

Проверки выполняются на сервере, включая скачивание файлов, просмотр DOCX и экспорт карточки по прямой ссылке. Журнал фиксирует изменения прав, реквизитов, этапов и версий. В журнале видна реальная учётная запись, если администратор действует от другого сотрудника.

**Пользователи:** создание, профиль, роль сотрудник/архивариус/администратор, сброс пароля, отключение. Сброс пароля, изменение роли и отключение завершают сеансы. Учётные записи сохраняются в истории. Отключение блокируется при незавершённых обязательствах и действующей блокировке файла. Собственные права администратора снять нельзя.

## Поручения и приёмка

1. В карточке выберите **Поручение / резолюция** либо создайте поручение в разделе **Мои задачи**.
2. Укажите текст, одного или нескольких исполнителей, контролёра и срок. Каждому исполнителю создаётся отдельное поручение.
3. Исполнитель открывает поручение и нажимает **Взять в работу**.
4. Заполняет обязательный отчёт и нажимает **Передать на приёмку**.
5. Инициатор либо контролёр выбирает **Принять исполнение** или **Вернуть на доработку** с причиной.

Статусы: Новое → В работе → На приёмке → Принято. Возврат снова открывает работу исполнителю. История отчётов и решений сохраняется. Изменение исполнителя, контролёра и срока требует причины; при смене исполнителя поручение становится новым. Отмена также требует причины.

В универсальном маршруте после приёмки всех поручений открывается следующий этап; в ручной схеме документ завершается. Архивирование до приёмки результатов запрещено. Самостоятельное поручение без документа видно исполнителю, инициатору, контролёру и администратору. Старые самостоятельные поручения v0.1, уже имевшие общую видимость, сохраняют её при переносе.

Раздел поручений содержит вкладки **Мои активные**, **На контроле**, **Завершённые**, **Все поручения**. Сроки просроченных активных поручений выделяются цветом.

## Дела и архив

Архивариус или администратор создаёт дело: уникальный индекс, название и срок хранения от 0 до 100 лет. **0 означает постоянное хранение**. Начальное дело 01-01 имеет демонстрационную настройку 5 лет; перед использованием настройте сроки по правилам своей организации.

Передача в архив доступна для утверждённого или исполненного документа после закрытия поручений, ознакомлений и блокировок файлов. Выберите открытое дело и место хранения оригинала. В архивной записи сохраняются индекс, название и срок дела на момент передачи. Последующие правки справочника эту запись не изменяют.

Карточка, обсуждение и файлы архива доступны только для чтения. Возврат оформляет архивариус или администратор с обязательной причиной; документ возвращается в прежний завершённый статус. Для изменения содержания автор/администратор затем открывает доработку. История архивирования сохраняется.

В архиве есть поиск по номеру, названию и месту оригинала, фильтры дела и года, отбор документов к пересмотру и **Опись CSV**. Дата пересмотра рассчитывается с 1 января года после передачи плюс срок дела. Это напоминание для рассмотрения; автоматического списания или уничтожения нет. Дело нельзя закрыть, пока в нём остаются неархивные документы.

## DOCX и версии вложений

Во вкладке **Вложения** можно:

- Загрузить DOCX/DOC/PDF, XLS/XLSX, TXT, PNG/JPG, SIG/P7S/CMS размером до 20 МБ.
- Создать **служебную записку** или **деловое письмо** из реквизитов карточки. Новый DOCX сразу сохраняется как вложение.
- Открыть **Текст DOCX**. Это текстовый просмотр: таблицы отображаются последовательно, изображения, комментарии и исправления следует проверять в редакторе.
- Скачать любую сохранённую версию; флажок показывает предыдущие версии.

Работа с Word / ONLYOFFICE Desktop:

1. У последней версии нажмите **Взять на редактирование**. Файл скачивается, устанавливается блокировка на 24 часа.
2. Откройте скачанную копию, внесите изменения и сохраните её на компьютере.
3. В той же группе вложения нажмите **Загрузить версию** и выберите исправленный файл.
4. Появится следующая версия, предыдущие сохранятся, блокировка снимется.

Для отказа от изменений нажмите **Снять блокировку**. Чужую блокировку снимает администратор с причиной. Запуск согласования при действующей блокировке запрещён. Нельзя отозвать права редактора или отключить его учётную запись, пока не завершено редактирование либо не снята блокировка. Истёкшая блокировка не продлевается автоматически: перед дальнейшей работой проверьте последнюю версию.

Сервер отклоняет загрузку поверх более новой исходной версии. Повторная загрузка через «Добавить файл» с тем же именем также создаёт версию существующего вложения. Кнопка **Загрузить версию** позволяет сохранить связь при переименовании файла.

Встроенного Word/ONLYOFFICE Document Server и автоматического обратного сохранения нет. Шаблоны находятся в `templates`; в поставке три DOCX, включая экспорт карточки. Шаблоны используют поля `{{title}}`, `{{number}}`, `{{description}}` и другие из `docx_ops.py`. Изменение шаблона не меняет уже созданные файлы.

## Локальная сеть и резервные копии

На серверном компьютере запустите **START_LAN.bat**. На других компьютерах откройте `http://IP_СЕРВЕРА:8000`, например `http://192.168.5.165:8000`. При необходимости разрешите входящий порт Python в частной сети Windows. Сотрудники входят под своими учётными записями.

Общая база и вложения должны храниться только на сервере, не в сетевой папке SQLite. На клиентских компьютерах достаточно браузера. Для остановки сервера используйте Ctrl+C.

**BACKUP.bat** создаёт ZIP в `backups`, содержащий согласованную копию SQLite и вложения. Храните резервные копии отдельно от рабочей папки.

Восстановление: остановите сервер, сохраните текущую `data` отдельно и распакуйте папку `data` из резервной копии рядом с `server.py`. Базу и вложения берите из одной копии. Затем запустите сервер. Первоначальные пароли ACCOUNTS.txt не включаются в резервный ZIP; действующие хеши паролей находятся в базе.

## Проверка после обновления

Сначала выполните **SCENARIO_CENTRAL_BANK_RU.md**. Для проверки функций ручного согласования выберите при создании соответствующий вариант маршрута.

1. Проверьте вход прежних пользователей, документы и скачивание старого вложения.
2. Создайте документ с категорией, метками и внешним номером.
3. Назначьте читателя и редактора. Убедитесь, что читатель не может менять реквизиты.
4. Создайте DOCX, возьмите его на редактирование, измените и загрузите новую версию.
5. Выполните согласование и утверждение.
6. Назначьте поручение, передайте отчёт на приёмку, верните с замечанием и затем примите результат.
7. Завершите ознакомление и передайте документ в архив. Скачайте опись и карточку DOCX.
8. Верните документ из архива с причиной, откройте доработку и проверьте журнал.

## Состав и проверка поставки

- `server.py`, `v3_core.py`, `universal.py`, `docx_ops.py` — сервер и прикладная логика; стандартная библиотека Python.
- `import_data.py` — перенос без перезаписи и без изменения исходной папки.
- `web/` — готовый интерфейс, не удаляйте.
- `frontend/` — исходники React/TypeScript и lockfile.
- `templates/` — поставляемые DOCX-шаблоны.
- `dev_tools/build_docx_templates.py` — необязательная пересборка шаблонов разработчиком; требует python-docx, пользователям приложения не нужна.
- `tests/` — автоматические проверки на временных базах.

Проверка без изменения рабочей базы:

```bat
py -3 -m unittest discover -s tests -v
```

Пересборка интерфейса нужна только разработчику: `cd frontend`, `pnpm install --frozen-lockfile`, `pnpm check`, `pnpm build`. Для этого нужны Node.js 22.13+ и зависимости; готовая СЭД работает без них.

## Результаты и границы версии

Автоматически проверены вход, права и прямые ссылки, карточка и связи, маршруты, поручения с приёмкой, архив и возврат, версии DOCX, блокировки и миграции v0.1/v0.2 и прежней сборки v0.3. Прошли 21 серверная проверка и 10 проверок модели/отрисовки согласования и доступности кнопок. TypeScript проверен, интерфейс пересобран. Сформированные DOCX визуально проверены после рендеринга.

Проверки выполнены в Linux. Непосредственный запуск v0.3 на Windows и нагрузочное испытание на 5–10 пользователей здесь не выполнялись. Браузер среды блокирует локальный адрес, поэтому визуальная проверка нового интерфейса не завершена.

Это расширенная локальная поставка для проверки на ваших сценариях, не завершённое промышленное внедрение. Сервер работает по HTTP без TLS. Архитектура хранит состояние организации в одной записи SQLite; одновременные сохранения проверяются по общей ревизии. Для постоянной эксплуатации потребуются отдельная настройка HTTPS, обслуживание, нормализованная база и проверка требований организации.

Не входят: криптографическая ЭЦП и проверка SIG/P7S/CMS, встроенное редактирование Office, почта/IMAP/SMS, OCR и полнотекстовый поиск по вложениям, юридически значимое архивное уничтожение. «Утвердить» фиксирует решение, но не создаёт электронную подпись. Журнал хранит прикладную историю и не является внешним неизменяемым хранилищем аудита.

В следующих этапах v0.3 остаются отдельные права по пользователям и отделам на каждое действие, соисполнители и вложения результатов поручений, доработка комментариев версий. Django/PostgreSQL, Windows Service и встроенный ONLYOFFICE — последующие работы. Эта сборка не объявляет весь план v0.3 завершённым.
