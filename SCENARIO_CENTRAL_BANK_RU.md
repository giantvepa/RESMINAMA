# Проверка входящего письма от Центрального банка

Сценарий для v0.3.0, сборка 2. Создайте новую карточку: перенесённые документы продолжают прежние маршруты. Используйте условные сведения и тестовый файл ответа. Выполняйте действия под отдельными учётными записями; для быстрой демонстрации администратор может переключать действующего сотрудника.

## 1 Регистрация секретарём

Войдите как `secretary` (Айна Мамедова). Создайте документ:

| Поле | Значение для проверки |
|---|---|
| Тип | Входящее письмо |
| Название | О предоставлении отчётности |
| Корреспондент | Центральный банк |
| Внешний номер | ЦБ-25/09 |
| Дата и дата регистрации | Текущая дата |
| Контрольный срок | Выберите будущую дату |
| Организация | Ваша организация |
| Куратор | Довлет Керимов |
| Основание | Запрос Центрального банка |
| Маршрут | Входящее: руководитель → резолюция → исполнение → ответ |

Сохраните. Номер должен иметь вид `ВХ-ГОД-0001` (порядковая часть зависит от прежних записей). При необходимости приложите письмо на вкладке «Вложения». Нажмите **Запустить маршрут**. Текущий этап — **Резолюция**.

## 2 Резолюция руководителя

Войдите как `director` (Довлет Керимов). Откройте письмо. Введите резолюцию «Подготовить отчётность и проект ответа», назначьте `it` и `finance`, выберите контролёром `director`, установите срок. Нажмите **Передать на исполнение**.

В карточке должны появиться два обязательных поручения. Резолюция сохраняется в реквизитах и журнале. Отправить ответ или передать документ в архив на этом этапе нельзя.

## 3 Исполнение и приёмка

Под `it` откройте своё поручение, нажмите **Взять в работу**, заполните отчёт и передайте на приёмку. Под `director` верните результат с комментарием «Уточнить показатели». Под `it` исправьте отчёт и передайте снова; под `director` примите его.

Повторите исполнение и приёмку для `finance`. Пока хотя бы одно поручение не принято, документ остаётся на исполнении. После приёмки обоих открывается этап регистрации ответа.

## 4 Регистрация ответа секретарём

Под `secretary` загрузите тестовый PDF/DOCX кнопкой **Загрузить файл отправленного ответа**. Укажите содержание ответа, получателя «Центральный банк», дату и способ отправки. Заполните дополнительные обязательные реквизиты исходящего письма, если администратор их настроил.

Нажмите **Зарегистрировать отправку**. Система фиксирует введённые сведения; реальную почту она не отправляет. Должна появиться связанная карточка **Исходящее письмо** с номером `ИСХ-ГОД-…`, отметкой отправки и копией приложенного файла. Откройте её по ссылке и скачайте файл. У входящего письма теперь активен этап **Архив**.

## 5 Архив

Под `secretary` вернитесь во входящее письмо. Нажмите **Передать в архив**, выберите дело и укажите место оригинала. Проверьте:

- Статус документа — «В архиве», маршрут завершён.
- Нет запуска нового процесса, поручения или ознакомления; доступ и реквизиты нельзя изменить.
- Вложения и карточка DOCX скачиваются.
- Журнал содержит резолюцию, отчёты и приёмку, переходы этапов, итерацию и файл ответа.
- Исходящий ответ связан с входящим; его архивирование выполняется отдельно.

Возврат из архива проверяйте под администратором или архивариусом с указанием причины. Если нужна новая итерация, после возврата откройте доработку и запустите маршрут повторно.

## 6 Проверка универсальности

Под администратором создайте в **Типах документов** новый тип «Запрос подразделения» с уникальным префиксом `ЗП`, базовой группой «Внутренний документ» и обязательным текстовым полем `subject_code` («Код вопроса»). Назначьте маршрут служебной записки. Создайте документ этого типа: без обязательного поля сохранение должно отклоняться; с ним карточка создаётся без изменения программного кода.

Измените название поля или участников шаблона. Уже созданная карточка должна сохранить свою копию настроек; новая — получить обновлённую. Для последовательного согласования задайте очередь стрелками и убедитесь, что второй участник не может принять решение раньше первого.

Дополнительные маршруты для проверки: **Договор** — Юрист, Финансы и IT → руководитель → исполнение → архив; **Приказ** — согласование → регистрация подписанного файла → ознакомление всеми назначенными сотрудниками → архив.

Автоматические серверные проверки этих сценариев включены в `tests/test_universal.py`. Работа интерфейса и запуск BAT на вашем Windows-компьютере требуют отдельной проверки.
